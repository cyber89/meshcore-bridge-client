# PI-02 — Credenciales en respuestas administrativas MQTT y CLI

Fecha: 2026-10-05. Estado: corregido en código; validación aislada realizada.

## Reproducción anterior al cambio

La configuración interna conservaba el PIN necesario para gestionar el dispositivo.
`AdminCommandHandler.handle({"action": "get_config"})` devolvía ese valor y lo
publicaba como JSON en el tópico administrativo MQTT. También ocurría con
`get_local_config` y cualquier comando CLI que añadía `config` al resultado.
El controlador REST ya utilizaba el redactor; los otros límites de salida no.
Un error de `set pin` podía repetir el PIN en `action`, `result` o una excepción.

Se añadieron primero doce casos con MQTT/SDK simulados y secretos sintéticos.
La ejecución previa produjo **11 fallos y 1 control aprobado**. Las aserciones
detectaron el PIN `654321` sin ocultar, credenciales anidadas sin redactar y el
eco de la acción sensible. Ningún dispositivo ni broker real participó.

```powershell
.venv/Scripts/python.exe -m pytest tests/test_admin_public_privacy.py -q --no-cov -p no:cacheprovider --basetemp tests/artifacts/pi02-before-tmp
```

## Cambio y contrato de salida

- `AdminCommandHandler.handle` devuelve una copia redactada de toda respuesta,
  incluidas estructuras SDK anidadas. Los errores existentes conservan sus códigos.
- `_publish_safe` aplica la misma redacción al JSON de cualquier ejecutor antes de
  entregarlo a MQTT. Un JSON inválido no se publica. Tópico y QoS se conservan.
- `CliCommandExecutor.execute` redacta su respuesta antes de publicar y devolverla,
  incluso cuando se utiliza directamente fuera del handler.
- Se reutiliza el redactor canónico de `protocol_types.py`. Las variantes de PIN
  (`pin`, `devicepin`, `ble_pin`, `blepin`) devuelven `0` y conservan `has_pin`.
  Contraseñas, PSK, tokens y claves privadas reconocidas mantienen la máscara
  `********`; campos no sensibles y valores de telemetría se conservan.
- El redactor de comandos ahora reconoce `set pin`/`set_pin` y variantes equivalentes
  de PIN y claves. `shared_utils.redact_sensitive_command` delega en esa definición,
  eliminando dos listas distintas de patrones. Las máscaras de comandos tienen
  longitud fija de ocho caracteres. Se verifica idempotencia.
- Los errores CLI de una acción sensible utilizan su versión redactada y un mensaje
  genérico para impedir que una excepción del SDK repita la credencial. Los errores
  ordinarios conservan su detalle. Un PIN inválido tampoco se repite en el resultado.

`get_local_config()` sigue proporcionando el snapshot privado necesario para la
administración interna. Las regresiones comprueban que ni la caché ni las entradas
del SDK pierden el PIN real; únicamente sus copias públicas se redactan. No cambia
el formato binario, el número de comandos de radio ni sus intervalos.

## Validación y evidencia mantenida

Las pruebas mantenidas se encuentran en
[`test_admin_public_privacy.py`](../../../tests/test_admin_public_privacy.py).
Sus 29 casos cubren configuración, entrada CLI directa, SDK anidado, publicación,
presencia del PIN, error sensible, variantes de comandos, idempotencia, texto
ordinario y rechazo de JSON inválido. Se utilizan el fixture temporal del proyecto
y mocks; no se inicia una estación operativa.

## Alcance y limitaciones

Este cambio cierra la fuga documentada PI-02 en respuestas administrativas. No
certifica protección de cualquier texto arbitrario ni de claves con nombres no
incluidos en el contrato canónico. El helper de comandos actúa sobre comandos
administrativos identificados, sin buscar PINs numéricos dentro de mensajes de
chat ordinarios. Los hallazgos de captura RF, otros contratos administrativos y
autenticación HTTP pertenecen a correcciones independientes.

La reproducción histórica de la auditoría no se ejecutó de nuevo ni se sobrescribió:
aquella comprobaba la existencia del defecto. Las pruebas nuevas expresan el
comportamiento correcto después del arreglo. No se transmitió RF ni se cargaron
archivos operativos; la integración con hardware queda fuera de esta evidencia.
